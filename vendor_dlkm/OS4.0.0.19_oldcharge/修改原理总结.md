# OS4.0.0.19 旧版快充移植原理

## 核心思路

不是把整个旧系统分区直接刷入，也不是只替换四五个 KO，而是：

1. 以手机当前官方 `OS4.0.0.19.XOBCNXM` 的 `vendor_dlkm` 分区作为完整基底。
2. 选择旧版和新版差异明确、与充电链相关的 28 个 KO。
3. 把这些 KO 的功能代码恢复为旧版，同时将导入/导出符号 CRC 适配到 `.19` 的模块 ABI。
4. 保留 `.19` 分区中其余相机、显示、USB、网络等模块，避免整分区跨版本回退。
5. 重建 EROFS、SELinux 标签和 AVB hashtree，保持原分区大小、UUID、salt 和 FEC 结构。

不能只替换四五个 KO，因为 `.19` 修改了多个充电模块之间的导出接口 CRC。单独换模块会出现
`disagrees about version`、`Unknown symbol`、充电链不完整或只有约 10 W 的问题。

## 主要回移内容

| 模块 | 处理目的 |
| --- | --- |
| `mca_strategy_quickchg.ko` | 恢复旧版功率爬升和快充状态机，去掉 `.19` 新增的循环降 FCC、`drop_fcc_para`、过压风险强制退出等软件策略 |
| `bq27z561.ko` | 恢复旧版电量计，去掉 `.19` 的云端 FG 固件更新通道和相关容量改写逻辑 |
| `mca_strategy_fg_comp.ko` | 去掉 `smooth_new` SOC 平滑、循环相关处理和 `.19` 新增容量监控策略 |
| `mca_strategy_buckchg.ko` | 恢复旧版 Buck 充电策略，去掉按循环次数降低浮压的路径 |
| `mca_business_battery_comp.ko` | 回移到与旧版策略接口匹配的版本，解决 `.19` 模块依赖关系 |
| 其余 23 个配套 KO | 同步 PD/PPS、无线充、CP、JEITA、温控、FG 接口和策略类接口，保证 28 个模块成套加载 |

## 没有修改的部分

- 没有修改内核 `vermagic`，全部保持 `.19` 的 `6.6.57` 模块版本标识。
- 没有把 `.16` 或 OS3 的整分区直接刷入。
- 没有改变分区大小、EROFS UUID、AVB salt、FEC roots 和 fingerprint。
- 没有删除 SC8581、PMIC、硬件 OVP、CP、PD 认证、电池认证、JEITA 和基础温度保护。
- 旧版策略减少的是新版软件限制和容量策略，不代表硬件保护被关闭。

## 验证结果

- 28 个 KO 全部可解析，模块验证结果为 `modules=28 failures=0`。
- 28 个核心 `.text` 与目标旧版一致，文件大小保持不变。
- 只修改了预期的 11 个导入 CRC 和 6 个导出 CRC。
- EROFS 回读 409 个文件，仅预期 28 个模块变化。
- 412 项 SELinux 标签检查无异常。
- AVB footer、`NONE` vbmeta 和 SHA-256 hashtree 验证通过。
- 已通过 `fastbootd` 写入 `vendor_dlkm_a`，手机正常开机且分区 SHA-256 与成品一致。

## 文件命名兼容说明

成品当前名称为 `vendor_dlkm_米15p_4.0.19.img`。旧文档曾使用
`vendor_dlkm_oldcharge_19.img`，两个名称指向同一份镜像内容；本次清理后统一使用当前名称。
