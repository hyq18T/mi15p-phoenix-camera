# 小米 15 Pro OS4.0.0.19 旧版快充移植

适用设备：小米 15 Pro（`haotian`，型号 `2410DPN6CC`，当前槽位 `_a`）

适用系统：`OS4.0.0.19.XOBCNXM`

> **重要：本仓库不提供 DTBO。**
>
> 必须自行使用 `OS3.0.305` 或更早、且与本机和分区完全匹配的 DTBO。成品 `vendor_dlkm` 恢复旧版充电 KO；快充爬升还需要对应旧版 DTBO。不要把其他机型或来源不明的 DTBO 混刷到本机。

## 成品用途

`vendor_dlkm_米15p_4.0.19.img` 以官方 `.19` 的 `vendor_dlkm` 分区为基底，只移植 28 个旧版充电相关 KO，并适配 `.19` 模块接口 CRC。其余模块、文件系统结构、分区大小、UUID、SELinux 标签和 AVB hashtree 均保持 `.19` 原样。

这次恢复的是旧版充电策略，并非关闭全部硬件保护。主要变化如下：

- `mca_strategy_quickchg.ko`：恢复旧版快速爬升逻辑，移除 `.19` 新增的循环级降 FCC、`drop_fcc_para`、过压风险强制退出快充等软件策略。
- `bq27z561.ko`：恢复旧版电量计逻辑，移除 `.19` 新增的云端 FG 固件更新通道。
- `mca_strategy_fg_comp.ko`：移除 `.19` 的 `smooth_new` SOC 平滑和循环相关策略。
- `mca_strategy_buckchg.ko`：恢复旧版降压充电逻辑，去掉按循环次数降低浮压的路径。
- `mca_business_battery_comp.ko`：回移到与旧版策略接口匹配的版本，并同步移植其余兼容 KO。
- SC8581、PMIC、硬件 OVP、CP、PD 认证、电池认证和基础温度保护仍然保留。

不要只把这批 KO 单独覆盖到手机现有文件；模块之间的导入/导出 CRC 和依赖关系必须成套匹配，否则可能出现无法开机或充电只有约 10 W 的情况。

## 刷入方法

`vendor_dlkm` 位于 `super` 动态分区中，必须在 `fastbootd` 模式写入，不能在普通 bootloader/fastboot 模式写入。

1. 确认手机已开启 USB 调试并连接电脑：

   ```powershell
   adb devices
   adb reboot fastboot
   ```

2. 进入 `fastbootd` 后确认设备状态：

   ```powershell
   fastboot devices
   fastboot getvar is-userspace
   ```

   `is-userspace` 必须返回 `yes`。如果仍返回 `no`，说明还在普通 bootloader，不能继续刷动态分区。

3. 确认当前槽位为 `a`：

   ```powershell
   fastboot getvar current-slot
   ```

4. 刷入旧版快充镜像：

   ```powershell
   fastboot flash vendor_dlkm_a "vendor_dlkm_米15p_4.0.19.img"
   ```

   当前已验证设备写的是 `vendor_dlkm_a`。如果当前槽位不是 `a`，不要套用本成品，先停止并重新确认系统与分区。

5. 刷入完成后重启：

   ```powershell
   fastboot reboot
   ```

首次开机可能比平时稍慢。开机后先确认系统版本、基带、Wi-Fi、USB、摄像头和普通充电正常，再测试快充；不要只依据充电动画判断，应同时查看实际功率、`current_now`、`voltage_now`、温度和内核充电日志。

## 回刷官方

如果无法开机、充电异常或需要恢复官方状态，重新进入 `fastbootd`，使用同一个刷入命令，只把镜像换成：

```text
vendor_dlkm_OS4.0.0.19_官方回刷.img
```

示例：

```powershell
fastboot flash vendor_dlkm_a "vendor_dlkm_OS4.0.0.19_官方回刷.img"
fastboot reboot
```

官方回刷镜像应与手机刷入前的 `vendor_dlkm_a` SHA-256 一致。若手机后来升级过系统，请重新从对应固件提取官方镜像，不要混用不同版本的 `vendor_dlkm`。

## 已验证项目

- 28 个 KO 全部可解析，`modules=28 failures=0`。
- 28 个 KO 的核心 `.text` 与目标旧版一致，文件大小保持不变。
- 仅预期修改 11 个导入 CRC、6 个导出 CRC；`vermagic` 全部保持 `.19` 的 `6.6.57`。
- EROFS 回读共 409 个文件，除 28 个充电模块外无其他文件变化。
- 412 项 SELinux 标签检查无异常。
- AVB footer、`NONE` vbmeta 和 SHA-256 hashtree 均验证通过。

以上为镜像静态验证结果；真实充电功率、温升和完整曲线仍需刷入后用手机实测。
