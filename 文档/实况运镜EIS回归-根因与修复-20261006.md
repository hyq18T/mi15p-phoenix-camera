# 实况运镜「内嵌视频只拍到一小块且发糊」——回归根因与修复

日期：2026-10-06　　设备：Xiaomi 15 Pro `2410DPN6CC` / `haotian`（`dc16f1e0`）
底包：相机 Phoenix-1.3.0（`9faff5bf…`，与 `Phoenix-1.3.0-15Pro-莱卡一瞬子档20261006` 一致）

## 一、结论

**这是 2026-09-30 已修复问题的「回归」，不是新 bug。**

上一轮（10-06 18:57）同步三件套时，LSPosed 模块被换回了 **09-28 的上游原始包**
（`0150B2D2…`，13,028,977 B），该包**不含任何本地 hook**（只有上游 `CameraV51Bridge$1..$70`），
于是 09-30 生效的 `CameraV51Bridge$73`（`isSupportLivePhotoEIS` 强制 false）失效，
实况 EIS 重新打开 → 录制流被 CamX OFE 几何模块裁切并偏移 → 内嵌视频只剩一小块、发糊。

## 二、证据

### 2.1 装机指纹（事故态）

| 项 | 值 | 判定 |
| --- | --- | --- |
| 设备内 `/data/app/.../com.android.camera/base.apk` | `9faff5bf…` | 相机侧是最新版，正常 |
| 设备内 `com.prometheus.camera.rev` | `0150B2D2…`（13,028,977 B） | **09-28 上游基线** |
| 反编译该包内的 `CameraV51Bridge$N` | 只有 `$1..$70` | 缺 `$71/$72/$73/$74` |
| 该包内 dex 字符串 `PhoenixLiveEIS` | 0 处 | EIS hook 不存在 |

### 2.2 App 侧日志（事故态，`MVIMG_20261006_193128`）

```
19:31:28.301 D/MCAM_LiveShotManager: startLiveShot E: mSupportEis = true, isSupportLiveShotV2Plus = false
19:31:28.301 D/MCAM_LiveShotManager: getVideoSize videoSize = 1080x1920
19:31:28.301 D/MCAM_LiveShotManager: wEis = 1008, hEis = 1792
19:31:28.301 D/MCAM_LiveShotManager: srcSize = 1080x1920，toEisSize = 1008x1792
19:31:28.917 D/CamX [OFE] camxofegeolibpass.cpp:983  residualCrop vid: offset.x 1604.49 / ai 0
19:31:28.917 D/CamX [OFE] camxofegeolibpass.cpp:1014 residualCrop vid: offset.y  878.00 / ai 0
```

`mSupportEis = true` + App 自己把 1080x1920 缩成 **1008x1792**（1080/1008 = 1.0714 倍 EIS 裁切），
且 `residualCrop` 偏移非零 → 裁切窗口被推到画面一角，正是用户看到的「只拍到右上角那一点」。

### 2.3 修复后（同一场景、同一预设、同一 4.2x 起点，`MVIMG_20261006_193549`）

```
D/MCAM_LiveShotManager: getVideoSize videoSize = 1080x1920      # 不再出现 wEis / toEisSize
```

| 样本 | 内嵌视频 | 帧数 | 时长 | 内嵌 mp4 体积 |
| --- | --- | --- | --- | --- |
| 修复前 `MVIMG_20261006_193128` | **1008x1792** | 62 | 2.064 s | 593,769 B |
| 修复后 `MVIMG_20261006_193549` | **1080x1920** | 64 | 2.131 s | 4,274,821 B |
| 超清实况（对照，`MVIMG_20261006_195632`） | 1080x1440 | — | — | 无 `residualCrop` |

### 2.4 画面内容定量（墙/地交界线在帧内的归一化行号）

方法：每帧转灰度、按行求均值（`PIL resize((1,256), BOX)`），取相邻行均值最大梯度处即交界线；
`edge` 为该梯度强度（0–255）。数值见 `06_测试/实况运镜EIS回归修复-20261006/交界线定量.txt`。

| 样本 | 交界线位置 | 边缘强度 | 判读 |
| --- | --- | --- | --- |
| 修复前 内嵌视频 | 0.004–0.660 乱跳 | **1–2** | 画面里**根本没有交界线**，只有一块无特征墙面 |
| 修复后 内嵌视频 | 第 1–53 帧恒 0.785 → 第 54–64 帧 0.762→0.582 | **30–31**（前段） | 有清晰交界线，且**跟随运镜平滑移动** |
| 修复后 静图 | 0.7695 | 27 | 与视频起始取景一致（静图取 4.2x 首帧） |

**运镜跟随度换算**：交界线相对画面中心的偏移由 `0.785-0.5 = 0.285` 缩到 `0.582-0.5 = 0.082`，
比值 **3.5 倍**；理论上 `4.2x → 1.0x` 应得到 `0.5 + 0.285/4.2 = 0.568`（实测 0.582，误差 2.4%）。
即：**内嵌视频现在完整跟随 4.2x→1.0x 的拉远动画**，而 10-01 报告里「内嵌视频只体现约 1.16 倍」的现象在本次修复态下不再复现。

## 三、修复动作

1. 从构建沙箱 `D:\GPT\_phoenix_build\lsp\`（含 `CameraV51Bridge$71..$74` 的最新源码）重建 LSP：
   `python tools\build_phoenix.py --mode lsp` → `CF804C34…`（13,033,073 B，`versionCode=2010300`）。
2. `adb install -r` 覆盖装机 + `am force-stop com.android.camera`。
3. 重建根模块 zip：只替换包内 `Phoenix_LSP_Phoenix-1.3.0.apk` 条目，其余 1356 条 CRC 逐条校验一致。
4. 把 `04_交付/Phoenix-1.3.0-15Pro-莱卡一瞬子档20261006/` 里的旧 LSP **原地替换**为修正版，
   避免该目录再被当成「最新版」同步出去（本次回归正是这样产生的）。
