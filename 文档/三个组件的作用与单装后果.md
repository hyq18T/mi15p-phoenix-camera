# 三个组件各自的作用，以及"只装相机 APK"会发生什么

分析日期：2026-09-28
证据：本机实机日志、两份 APK 的 dex `class_defs` 解析、模块载荷清单
配套数据：`06_测试/LSP与模块作用分析/`（含分析脚本与结果）

## 结论速览

| 组件 | 包名 / 位置 | 角色 | 少了它会怎样 |
| --- | --- | --- | --- |
| **相机 APK** | `com.android.camera` | 相机主体：510 底包 + 410 个补丁改写 + 自带 6 个 Phoenix 类 | — |
| **LSP 扩展 APK** | `com.prometheus.camera.rev` | Xposed 模块：409 个类、**172 个 hook 点**，注入相机 / 相册编辑器 / system | **相机启动即崩**（实测 `NoClassDefFoundError`） |
| **Magisk 模块** | `/data/adb/modules/legend17u_14u_local` | "装 + 喂 + 挂"：安装两个 APK、挂 `/odm` 资产、播种水印与滤镜、配置 LSPosed 作用域、sepolicy | 相机能开，但缺视频 LUT / 水印资产 / 初始配置 |

一句话概括分工：**相机 APK 承载"外观与改写过的 MIUI 实现"，Phoenix 新增的逻辑几乎全在 LSP 侧。**

## 一、LSP 模块起什么作用

### 身份与注入范围

| 项 | 值 |
| --- | --- |
| 包名 | `com.prometheus.camera.rev` |
| 声明 | `xposedmodule=true`、`xposedminversion=82`、`staticScope=true` |
| 作用域（`assets/META-INF/xposed/scope.list`） | `system`、`com.android.camera`、`com.miui.mediaeditor` |
| 体量 | **409 个类**（dex `class_defs` 实测）、**172 处 `findAndHookMethod`** |

`assets/xposed_init` 声明了 13 个入口类：

```
com.prometheus.camera.rev.CombinedEntryPoint      com.prometheus.camera.rev.StreetCapabilities
com.prometheus.camera.colordev.EntryPoint         com.prometheus.camera.rev.StreetPortraitStyle
com.prometheus.camera.rev.FeatureEntryPoint       com.prometheus.camera.rev.WatermarkFilterIcon
com.prometheus.camera.rev.SoftFocusPanel          com.prometheus.camera.rev.PhoenixCompatFix
com.prometheus.camera.rev.StreetUiEntryPoint      com.nezha.q0fix.PhoenixQ0Fix
com.prometheus.camera.rev.AppPhotoEffects         com.prometheus.camera.rev.VideoLutCatalog
com.prometheus.camera.rev.VideoLutMonitor         com.prometheus.camera.rev.VideoLutQuality
```

### 它做的三类事

**1）给相机"补类"——这是硬依赖，不是增强**

相机 APK 的 dex 里只定义了 **6 个** `com/prometheus/**` 类，全部属于"设置备份"功能：

```
Lcom/prometheus/camera/backup/BackupPreferenceFragment;      Lcom/prometheus/camera/backup/SettingsBackupArchive;
Lcom/prometheus/camera/backup/BackupPreferenceFragment$1;    Lcom/prometheus/camera/backup/SettingsBackupArchive$RestoreResult;
Lcom/prometheus/camera/backup/BackupScope;                   Lcom/prometheus/camera/backup/SettingsBackupArchive$Scope;
```

而补丁改写的相机代码直接引用了另外 3 个**只在 LSP 里定义**的类：

| 只在 LSP 内的类 | 被哪些相机补丁类引用 |
| --- | --- |
| `Lcom/prometheus/camera/filters/GalleryFilterCatalog;` | `smali_classes5/ri/e.smali` |
| `Lcom/prometheus/camera/filters/CustomLutStore;` | `smali_classes10/wu.1/g.smali`、`smali/o3.1/b.smali` |
| `Lcom/prometheus/camera/filters/FilterManagementActivity;` | `smali/com/android/camera/fragment/settings/CameraAdvancePreferenceFragment.smali` |

这 4 个补丁类只要被走到就会 `NoClassDefFoundError`。其中 `ri/e` 在**相机预览启动链路**上（见第三节），所以后果是崩溃而不是功能缺失。

**2）运行期改写相机行为**

| 功能 | 主要类 |
| --- | --- |
| 视频 LUT 画质解锁、HDR 常开 | `VideoLutQuality`、`VideoLutMonitor`、`VideoLutCatalog`、`FeatureEntryPoint` |
| 黑柔 / 白柔面板 | `SoftFocusPanel` |
| 水印图标与发布 | `WatermarkFilterIcon`、`CameraV51Bridge` |
| 机型名与两项元数据开关（EXIF `Model`/`XiaomiProduct`、`XiaomiAuxiliaryInfo.waterName`） | `DeviceNameOverride`、`CameraWatermarkBridge`、`MetadataSyncPreferenceFragment` |
| 街拍相关能力与 UI | `StreetCapabilities`、`StreetPortraitStyle`、`StreetUiEntryPoint` |
| 兼容性兜底 | `PhoenixCompatFix`、`PhoenixQ0Fix` |

运行期旁证（设备 `prometheus_camera_settings.xml`）：`phoenix_video_lut_quality_unlock=true`、`prometheus_hdr_always_on=true`。

**3）桥接相册编辑器**

`GalleryV24043Bridge`、`MediaEditorWatermarkBridge` 用 `Class.forName` 直接查相册编辑器的混淆类名（`Ob.l`、`qd.i`、`ud.b`、`ud.h`、`ud.e`、`Bd.i$a`、`on.a`、`vg.q`）。**这正是"必须 2.4.0.4.3"的由来**——实测设备上的 `2.4.0.5.2` 已缺 5/8，该链路失效（详见 `05_文档/相册编辑器版本绑定实测-2.4.0.5.2.md`）。

## 二、Magisk 模块起什么作用

模块**不参与运行期 hook**，它负责"把东西装进去、喂到正确位置、开机挂起来"。

### 安装期（`customize.sh`，13425 B）

| 动作 | 说明 |
| --- | --- |
| 环境检查 | 确认相册编辑器存在、ROOT 管理器类型 |
| 安装两个 APK | `pm install -r` 装 LSP（`com.prometheus.camera.rev`）与相机（`com.android.camera`） |
| 整理 ODM 目录 | Magisk 下保留 `system/odm` 载荷，开机合并进 `/odm` |
| 写资产 | 42 个内置预设滤镜、用户滤镜目录、相机与相册编辑器的本地水印模板（各 16 项） |
| 权限与 sepolicy | `sepolicy.rule`（priv_app 与 hal_misys_vendor 的 binder 权限） |
| 自检 | `install-self-check.sh`，全部通过才继续 |

安装**不要求清数据**（本机实测在已有相机数据上覆盖成功）。

### 载荷（模块目录内的静态资产）

| 目录 | 文件数 | 体积 | 用途 |
| --- | --- | --- | --- |
| `system/odm/etc/camera/videofilter` | 69 | 42.84 MB（与 watermark 合计） | 视频滤镜 LUT（含 11 个 Leica LUT） |
| `system/odm/etc/camera/xiaomi/watermark` | 108 | 同上 | 水印图标资产 |
| `watermark_cache` | 1125 | 20.99 MB | 播种到相机 / 相册编辑器的水印素材 |
| `watermark_suffix` | 37 | 0.33 MB | 徕卡后缀水印 |
| `content` | 2 | 0.02 MB | 本地水印清单 `.tsv` 与摘要 `.commit` |

### 开机期

| 脚本 | 职责 |
| --- | --- |
| `post-fs-data.sh` | 复制合并 `/odm` 子树并做目录级 bind（本项目修复过的部分） |
| `service.sh` | 配置 LSPosed 作用域（`ScopeInstaller`）→ 等应用数据目录 → `seed-watermark.sh` → 启动 LUT / by-Leica / 本地水印同步 |
| `sync-custom-luts.sh` | 用户滤镜从相机的 `files/prometheus/custom_luts` 同步到 `/data/vendor/camera` |
| `sync-by-leica-assets.sh` | 相机完成 by-LEICA 资产事务后，把校验过的文件交给相册编辑器 |
| `sync-local-watermarks.sh` | 监听并同步本地水印到相册编辑器 |
| `sync-watermark-suffix.sh` | 每 30 秒同步水印后缀 |
| `action.sh` | 不重装 APK 的前提下重建模块管辖的应用资产（数据恢复用） |

本机开机日志实测：

```
成功：相机、相册编辑器和系统框架作用域已启用
成功：相机与相册本地水印已初始化
已启动滤镜同步 / 已启动动态机型整图同步 / 已启动相册本地水印监听
```

## 三、如果只装相机 APK 会怎样

### 1）装不进去（除非有核心破解）

```
$ apksigner verify Phoenix_Camera_Phoenix-1.3.0.apk
DOES NOT VERIFY
ERROR: APK Signature Scheme v3 signer #1: APK integrity check failed.
       CHUNKED_SHA256 digest mismatch.
```

签名块是从官方底包原样搬过来的（证书仍是小米 MIUI 相机证书，报错是**摘要不匹配**而不是"无证书"），但 APK 内容已被重建，所以完整性校验必然失败。**安装依赖核心破解跳过校验。**

### 2）装上也会崩——本机实拍到的崩溃栈

`06_测试/实机验证/logcat-01-安装后首次启动.log`（2026-09-28 01:02:14，PID 583）：

```
E AndroidRuntime: FATAL EXCEPTION: CameraSetup
E AndroidRuntime: Process: com.android.camera, PID: 583
E AndroidRuntime: java.lang.NoClassDefFoundError:
    Failed resolution of: Lcom/prometheus/camera/filters/GalleryFilterCatalog;
E AndroidRuntime:   at ri.e.d(Unknown Source:238)
E AndroidRuntime:   at com.xiaomi.camera.effect.EffectController.b(...)
E AndroidRuntime:   at com.xiaomi.camera.effect.EffectController.b0(...)
E AndroidRuntime:   at l6.b.j(...)
E AndroidRuntime:   at com.android.camera.module.Camera2Module.updateAiScene(...)
E AndroidRuntime:   at com.android.camera.module.Camera2Module.consumePreference(...)
E AndroidRuntime: Caused by: java.lang.ClassNotFoundException:
    com.prometheus.camera.filters.GalleryFilterCatalog
```

崩溃点在 `Camera2Module.updateAiScene` → `EffectController` → `ri.e.d`，也就是**打开相机进入预览的必经路径**。所以不是"少个功能"，而是相机不可用。

注意：该日志对应的是"LSP 的 APK 已由模块安装，但 Xposed 模块尚未在 LSPosed 中启用生效"的状态。**"完全不装 LSP"与"装了但没生效"表现完全相同**，因为类是由 Xposed 把模块 dex 注入相机进程后才可解析的。

### 3）即使类能解析，缺模块仍然残缺

| 缺什么 | 后果 |
| --- | --- |
| `system/odm` 载荷 | 视频滤镜 LUT 只剩手机原生的 58 个（缺 11 个 Leica LUT）、水印图标缺 2 个 |
| `watermark_cache` / `watermark_suffix` / `content` | 相机与相册编辑器里没有本地水印与徕卡模板 |
| `customize.sh` 的 42 个预设滤镜 | 滤镜槽位为空 |
| `service.sh` 的作用域配置 | LSPosed 作用域不会自动勾选（需手动勾 `com.android.camera`、`com.miui.mediaeditor`、`system`） |
| `sepolicy.rule` | `priv_app` 与 `hal_misys_vendor` 的 binder 调用许可缺失 |
| `sync-*.sh` | 相机 ↔ 相册编辑器的滤镜/水印同步不会发生 |

### 4）三件套的正确关系

```
Magisk 模块  ──安装──▶  相机 APK  +  LSP APK
     │                        │            │
     │                        │            └─ Xposed 注入相机进程，补上缺失的类
     │                        └─ 相机主体（510 + 补丁改写）
     └──挂 /odm 资产 + 播种滤镜/水印 + 配置作用域
```

三者是**强耦合**：相机缺 LSP 会崩，LSP 缺模块则不会被装/不会生效，模块缺相机 APK 则只是空壳。这也是为什么上游把它打包成 `AllInOne.zip` 一起刷。

## 复现命令

```powershell
$proj="D:\GPT\2026-09-27_小米15Pro_Phoenix相机适配"
$dep="D:\GPT\_phx_dep"
# 解出两个 APK 的 dex，再解析 class_defs（区分“定义”与“仅字符串引用”）
node "$proj\06_测试\LSP与模块作用分析\dex_classdef_dump.js" "$dep\camera" "com/prometheus/" "$proj\06_测试\LSP与模块作用分析\camera-apk-defined-prometheus.txt"
node "$proj\06_测试\LSP与模块作用分析\dex_classdef_dump.js" "$dep\lsp"    "com/prometheus/" "$proj\06_测试\LSP与模块作用分析\lsp-apk-defined-prometheus.txt"

# 签名校验
java -jar D:\GPT\_phoenix_build\_android-sdk\build-tools\35.0.0\lib\apksigner.jar verify --verbose `
  "$proj\04_交付\Phoenix-1.3.0\Phoenix_Camera_Phoenix-1.3.0.apk"
```

> 提醒：`dex_class_probe.js` / `dex_class_dump.js` 读的是**字符串表**，只能证明"存在引用"；要判断类是否真的被定义必须用 `dex_classdef_dump.js` 解析 `class_defs`。本次一开始就踩过这个坑——字符串表里能查到 `GalleryFilterCatalog`，但相机 APK 其实只定义了 6 个 Phoenix 类。
