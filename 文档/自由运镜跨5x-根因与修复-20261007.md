# 自由运镜跨 5x 物理切镜头 —— 根因与修复（2026-10-07）

## 现象
实况运镜「自由运镜」录制的内嵌视频，在推拉中途出现一次硬闪（镜头整个跳一下）。
上一轮量化为第 46–55 帧差分从 0.5 突增到 19–24。

## 根因
15 Pro 长焦（tele）物理起点是 5x，而自由运镜默认区间是 `4.2:8.4`，
推拉过程必然从「主摄数码变焦」跨越到「长焦」，HAL 在 5x 处切换物理镜头 → 画面硬切。

区间来自 `Lv2/d0;->m(lensType, key)`，其值取自机型配置（`Le/a`），
且会被运行时的 `pref_master_live_current_range_key` 覆盖。
往 prefs 里硬写区间无效：进模式时 App 会重写该键。

## 修复
新增 LSP hook：`PhoenixMasterLiveTailBridge$7` 钩 `Lv2/d0;->m`。

- 入参实测为 `args = [key, lensType]`（自由运镜 `["3","tele"]`，主角运镜 `["2","wide"]`），
  因此门控必须用 **args[0]**。
- 命中 `key == "3"` 时，把返回数组中的 `"4.2"` 改写为 `"5.0"`（两端都查，兼容反向区间）。
- 同一方法的调用方还有 `R4/i`（缩放条 UI），故 UI 标签一并变为 `5 » 8.4`。

## 踩过的坑（务必记住）
1. `if-nez` / `if-eqz` 写反：探针里写成 `if-nez v0, :done`（result 非空时跳走），
   导致 result 与替换逻辑被整体跳过、日志为空，白白多花一轮定位。
2. 门控字段猜错：先按 `args[1]` 判定，实际 key 在 `args[0]`，导致 hook 全程空转。
3. 无门控会误伤：主角运镜（`key=2`）的区间首项同样是 `4.2`，不加门控会被一起改成 `5.0`。

  但用户反馈第三方装三件套后看不到莱卡一瞬入口，**仍是待复核项，本轮无实机证据**。

## 追加（2026-10-07 晚）：主角运镜是否也要 4.2 → 5.0？

**结论：不要改。**

实测（真机 `pref_master_live_key=2`，实况运镜 → 主角运镜）：

```
resetZoomRatioBeforeRecording: lensType = wide zoomrange = 4.2:1 startZoomRatio = 4.2 actualZoomRatio = 4.2
startAutoZoom(): zoomSpeed = 2.0 ZoomRange = 4.2:1.0 fromEvent = 2
resetZoomRatioAfterRecording: lensType = wide zoomRange = 4.2:1 startZoomRatio = 4.2 actualZoomRatio = 1.0
startAutoZoom(): zoomSpeed = 0.45749998 ZoomRange = 1.0:4.2 fromEvent = 3
```

- 主角运镜挂在 **`wide`（主摄）** 上、区间 `4.2 → 1.0`，是**向外拉远**，全程不跨越 5x；
- logcat 同时可见 `MCAM_MiCamera2: disableSat: E/X`、`applySmoothTransition: false` ——
  该模式下 SAT 被关闭，走单镜头数字变焦，**不存在物理切镜头**。
- 因此「起点 4.2 撞上 5x 长焦」这个病因在主角运镜里不成立；
  强行改 5.0 反而会把特效起始视角收窄、并可能正好踩在长焦接管阈值上。

**但主角运镜确有另一个独立缺陷**（与 4.2/5.0 无关）：
内嵌视频在 `t≈1.73s`（第 53 帧）有一次 12.84 的差值突跳（相邻帧基线仅 0.2–0.3），
抽帧目视确认是**一次比邻近帧更大的缩放台阶**（画面「顿一下」），不是镜头切换。
PTS 检查：帧间隔全部为 0.033s，排除掉帧假象。
成因待查（疑似动画收尾时的对齐/吸附），需白天有可辨纹理的场景复现。
