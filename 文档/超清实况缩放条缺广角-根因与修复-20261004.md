# 超清实况缩放条缺广角：根因与修复（15 Pro）

- 日期：2026-10-04
- 现象：「实况运镜 → 超清实况」缩放快捷条只有 `1x / 2`，广角档缺失
- 结论：**机型表缺 `0xE7` 条目**，单文件追加即可修复；已实机验证

## 一、调用链（自下而上）

```
pl/c.smali  (ZoomSlidingPanelFragment 初始化)   scale/b;->N0
  -> Lcom/android/camera/data/data/j;->W(IZZ[F)Ljava/util/ArrayList;   (j.smali:6058)
     -> Lur/i;->q(IZZ[F)[F                                            (smali_classes10/ur.1/i.smali:1563)
        p1 != 0 -> Je/c;->e  (com.mi.device.common.Common 实例)
                    运行时实为 com.mi.device.Haotian
                    -> 虚调用 v1()Landroid/util/SparseArray;
        p1 == 0 -> C1()Landroid/util/SparseArray;   (仅 0xa3 / 0xa2，与本问题无关)
```

`jl/d.smali:243 c(IZZ)[F` 是另一条取档路径，同样先 `j;->R(I)[F`，再经 `kl/*` 过滤器链。

## 二、`j.R(I)` 对 `0xE7` 的处理（j.smali:3940）

- `3943: const/4 v0, 0x1`（后续 `q()` 的第 2 参恒为 1，即走机型表）
- `3989: new-array v7, v6(=0)` —— 空数组占位
- `4031: const/16 v11, 0xe7` / `4033: if-eq p0, v11, :cond_a`
- `:cond_a`(4259) → `:goto_4`(4260)：`v7` 长度为 0 → `4265: ur/i;->q(0xE7, 1, 1, v2)`，`v2` 兜底为 `[1.0, 2.0]`（`Je/c;->K1()Z == true` 时）
- `:cond_b`(4269)：`E;->e0()Z`；**false → `:cond_17` 直接用上面 `q()` 的结果**，true → 走另一条"重建档位"分支

### 2.1 为什么 `E.e0()` 一定为 false（直板 15 Pro）

```
E.e0()  = K2/b.b0() && (v2/l0.a & 1)
K2/b.b0() = V() || Z() || a0()
V()/Z()/a0() = (K2/b.n() == Z5/l.k / l.l / l.n)
Z5/l 枚举：a INVALID_MODE, b NORMAL_MODE, c PAD_MODE, d BOOK_MODE, e LAPTOP_MODE,
          f REVERSAL_LAPTOP_MODE, g VER_GALLERY_MODE, h HOR_GALLERY_MODE, i FLIP_MODE,
          j REVERSAL_FLIP_MODE, k SIMPLE_MODE, l REVERSAL_SIMPLE_MODE, m WIRELESS_MODE,
          n SECOND_SCREEN_MODE ...
```

`k/l/n` 均为折叠屏/副屏/多屏形态。直板 15 Pro 为 `NORMAL_MODE(b)`，故 `b0()==false` → `e0()==false` → 走 `:cond_17`，**机型表即唯一来源**。

### 2.2 `q()` 的实现（`smali_classes10/ur.1/i.smali:1563`）

```
p1 != 0 -> Je/c;->e -> v1()Landroid/util/SparseArray;
           SparseArray 命中 p0 -> 返回该数组，否则返回兜底数组 p3
p1 == 0 -> Je/c;->e -> C1()Landroid/util/SparseArray;（key 为 p0，值为 SparseArray）
```

## 三、机型类的定位

- `Je/e;->G0()` 反射构造：`Class.forName("com.mi.device." + k(Build.DEVICE) + suffix)`
- 类名经 `Gt/a;->C(ILjava/lang/String;)` 逐字符 XOR 解密，key 由 `Uf/c;->a(String)` 用 `hashCode()` 查 `Uf/a;->a` 得到
- 实机 `ro.product.device=haotian`、`ro.boot.camera.config=`（空）→ 明文 `com.mi.device.Haotian`
- 混淆类名：`L潩潥潧漤潧潣漤潮潯潼潣潩潯漤潂潫潥潾潣潫潤;`
- 文件：`smali_classes3\潩潥潧漤潧潣漤潮潯潼潣潩潯漤潂潫潥潾潣潫潤.smali`

## 四、根因

`Haotian.v1()`（该文件 `1010` 行起）只登记了：

| key | 数组 |
| --- | --- |
| `0xa3` | 0.6, 1, 2, 5, 10, 30, 60, 120 |
| `0xaf` | 0.6, 1, 5 |
| `0xad` | 0.6, 1, 5 |
| `0xac` | 0.6, 1, 5 |
| `0xab` | 1, 2, 5 |

**没有 `0xE7`**。官方 510 底包里该文件与机型表完全一致（`work/camera-base` 比对），说明 `0xE7`（实况运镜/超清实况）本就未在 15 Pro 的登记表中，`q()` 只能返回兜底 `[1.0, 2.0]`。

对照上游 Phoenix 补丁覆盖的其它机型（例：`皪皦皤盧皤皠盧皭皬皿皠皪皬盧皋皰皻皦皧.smali`），它们都在 `v1()` 末尾登记了 `0xE7`，且数组与其 `0xa3` 同档 —— 即上游本就认为该 mode 需要广角档。

## 五、修复

文件：`camera/patch/smali_classes3/潩潥潧漤潧潣漤潮潯潼潣潩潯漤潂潫潥潾潣潫潤.smali`（`patch.json` 已登记，无需改动清单）

在 `v1()` 末尾（`return-object p0` 之前）追加：

```smali
# Phoenix-15Pro: 超清实况(0xe7) 补回广角/长焦档位 [0.6, 1.0, 2.0, 5.0, 10.0]
const v0, 0x3f19999a    # 0.6f
invoke-static {v0}, Ljava/lang/Float;->valueOf(F)Ljava/lang/Float;
move-result-object v0
const/high16 v1, 0x3f800000    # 1.0f
invoke-static {v1}, Ljava/lang/Float;->valueOf(F)Ljava/lang/Float;
move-result-object v1
const/high16 v4, 0x41200000    # 10.0f
invoke-static {v4}, Ljava/lang/Float;->valueOf(F)Ljava/lang/Float;
move-result-object v4
filled-new-array {v0, v1, v2, v3, v4}, [Ljava/lang/Float;
move-result-object v0
const/16 v5, 0xe7
invoke-virtual {p0, v5, v0}, Landroid/util/SparseArray;->put(ILjava/lang/Object;)V
```

寄存器安全性：插入点处 `v2` / `v3` 分别仍是 `Float(2.0)` / `Float(5.0)`（`1038`–`1048` 行设置后未被覆盖），被复用于数组元素；`v0/v1/v4/v5` 在 `return-object p0` 前不再被使用。方法与 `.locals 6` 匹配。改动净增 702 字节，其余字节逐一比对未变。

## 六、验证

见 `04_交付/Phoenix-1.3.0-15Pro-超清实况广角20261004/说明.md` 与 `06_测试/超清实况广角修复-20261004/`：档位出现、`0.6x` 真超广角、`10x` 正常、实拍出片、预设与拍照模式无回归。

## 七、可选后续

- 若确认该模式下不应出现 `5x / 10x`（当前为数字裁切，不切潜望），把数组改为 `[0.6, 1.0, 2.0]` 重新构建即可，改动同点位。
- `0xE7` 若同时服务三个运镜预设（超清实况/主角运镜/自由运镜），本次改动对三者同时生效；已确认三预设入口与切换均正常。
