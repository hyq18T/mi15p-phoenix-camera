# 实况运镜「内嵌视频变焦丢失 + 片尾跳变」根因报告

日期：2026-10-01　　设备：Xiaomi 15 Pro `2410DPN6CC` / `haotian`
环境：Phoenix-1.3.0 三件套（相机底包 6.6.000510.0 + LSP 模块 + Magisk 模块）

## 一、现象（用户描述）

- 「主角运镜」「自由运镜」拍出来的动态照片**内嵌视频不对**；超清实况正常。
- 「拍摄完之后他在后面应该停留个一两秒，他是直接停留了一下然后直接就闪完直接结束了。」

## 二、本轮新增的诊断手段

1. **打开官方相机日志**（无需改代码）：
   `adb shell su -c "setprop log.tag.MCAM_ VERBOSE"`
   小米相机的 `com.android.camera.log.LogUtil.isLoggable()` 会用 `android.util.Log.isLoggable("MCAM_", level)` 判级别，
   设置该属性后官方 `MCAM_*` 全量日志进入 logcat，可拿到毫秒级时间线。
2. **内嵌视频定量分析**：抽出 MVIMG 内嵌 mp4 → `ffmpeg` 降到 64×128 灰度 → 逐帧 MAD（平均绝对差）+ 接触表目视。
3. **窗口实验**：用 LSP 模块 `CameraV51Bridge$74` 把片尾时间戳从 `base+2.6075s` 改成 `base+4.9575s`，验证「窗口」与「成片内容」的因果关系。

## 四、结论

1. **内嵌视频流不跟随逻辑变焦。** 日志证明变焦值一路下发到了设备（`applyZoomRatio(): apply zoom ratio to device = 4.198557 … 1.0`），但 1080×1920 的电影流成片里只体现约 1.16 倍的取景变化。即：预览/静态图走逻辑变焦，**录制流没有吃到同一套裁切**。
2. **片尾「闪」= EIS 裁切释放。** 两次实拍（窗口差 2.35s）中，这段变化始终出现在**片尾前 0.13s**，与「录制停止」严格对齐；幅度 1.16 倍 ≈ 典型 EIS 裁切量。与用户实测「关掉视频防抖后视频是全幅」完全一致。
3. **成片长度被固定在 64 帧 / 2.13s，与窗口无关**：把片尾延长 2.35s 只让 EOS 推迟、`videoLength` 变大，成片仍是 64 帧，变化段仍贴在片尾。
4. **`$74` 的片尾延长在视频轨上会被 `CircularMediaRecorderV2.fixSnapshot` 重算覆盖**（音频轨保留 `base+2.6075s`），这是 `$74` 无法延长成片的直接原因。
5. 15 Pro 的 HAL 缺供应商 tag：
   `E VendorTagDescriptor: lookupTag: Tag name 'enableMasterLivePhoto' does not exist.`
   上游机型靠该 tag 让 HAL 在**录制流**上执行运镜；缺失后没有等价替代路径。

## 五、可行动选项

| 方案 | 内容 | 效果 | 风险 |
| --- | --- | --- | --- |
| A | 实况运镜里关掉「视频防抖」 | 消除片尾跳变（代价：失去防抖） | 零 |
| B | 改 `MasterLiveModule` 动画缓动为全程线性 | 预览不再「先不动后猛拉」；**不能**让内嵌视频出现变焦 | 低 |
| C | 让录制流也接受逻辑裁切（自行补 HAL 缺失的 `enableMasterLivePhoto` 行为） | 理论根治 | 高：需改 `Camera2Module`/`CaptureRequestBuilder` 的重复请求，回归面覆盖预览与拍照链路 |
